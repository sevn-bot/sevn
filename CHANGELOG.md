## [Unreleased]

- Pair devices and reach several hosts over a tailnet without the edge. `sevn pair` or Settings → Devices issues a one-time ticket (QR or 8-character code, 10-minute TTL, stored only as SHA-256) with a scope; a paired device keeps its own non-extractable Ed25519 key per host and, from outside the host, must answer a host-signed challenge over a fresh nonce and the origin it dialled. A bad signature, an unknown or revoked device, an origin outside `http.allowed_hosts`, or a reused nonce closes with 4001; revoking a device (`devices.revoke` or `sevn devices revoke`) closes its live sessions with 4003 within a second. See `docs/remote-direct.md` for Tailscale `serve`, Headscale, NetBird, ZeroTier, WireGuard and containers.

- A paired device no longer trusts a host that skips the signed challenge, and wrong short codes can no longer lock out pairing by QR code or full ticket: only the guessable short code is rate limited. The serving host's own connection now shows a refusal instead of reconnecting forever, the devices screen offers no Revoke for this browser's own device, and a retry after a refused QR scan keeps the scanned ticket.

- Proxied requests are not treated as local. A request counts as loopback only from a loopback address, with a loopback `Host` and the bound port, and with none of `Forwarded`, `X-Forwarded-*`, `X-Real-IP` or the `Tailscale-*` headers present; those headers are never read as identity. A proxy that rewrites `Host` to loopback and adds no such header still looks local, and still needs the token or cookie. `/auth/login` is loopback only (403 otherwise), so a browser on a container's published port pairs with an owner ticket from `docker exec <container> sevn pair --scope owner`. New settings `http.allowed_hosts`, `allowed_origins`, `public_scheme` and `connect_src` feed the Host and Origin guards and the SPA's CSP `connect-src`; `sevn serve --host 0.0.0.0` with no allowed hosts exits 2. The CLI and `sevn probe` reach the host over a private unix control socket (`run/control.sock`, 0600, used only when it and its directory belong to the current user), so they also work on an overlay bind.

- The web app holds a profile per paired host and connects to all of them: bots grouped by host with a reachability dot, one Inbox and one Approvals view, and chat with a bot on any paired host at `/hosts/<host>/bots/<bot>`. Before dialling, a direct URL must be `wss://`, loopback, or `ws://` to an address in the profile's private networks (Tailscale's ranges by default) unless plain `ws://` is turned on for that host. A challenge that does not verify against the pinned host key stops that host with "Host identity changed — re-pair to continue" and a hint about `http.allowed_hosts`.

- Paired devices with the `member` scope currently get owner rights, including sending messages, answering approvals and administering devices. The stored scope stays `member`, so a later release can narrow it without re-pairing; `read_only` devices are refused every owner-only method, an `owner` ticket needs a loopback owner session, and the last owner device cannot be revoked remotely.

- mergeCraft reviews get a 20M token budget, because the 2M default failed the job on large pull requests even after the reviewer approved.

- Tracing over OTLP to Logfire or Datadog: one trace per message, secrets redacted, content off by default. The host can export OTel traces to Logfire or to any OTLP collector, including a Datadog Agent (`datadog-agent`) or Datadog's agentless intake (`datadog-agentless`, which also asks Datadog to compute APM trace metrics and marks traces for LLM Observability), through a new `[observability]` config section. Nothing is exported unless an exporter is set or a Logfire token is stored. Header values must be `secret://` references, registered secrets and key patterns are scrubbed from every exported span, and an unreachable collector is reported once and never delays startup or shutdown past 5 seconds. Each message is one trace: a `job` span, a `route.decide` span per routing step, and a `turn` span with its model, token counts, cost and stop reason, plus the model and tool calls under it (`tool.<name>` for the Claude runtime). The trace context is stored on the job (`jobs.trace_parent`, migration `0010_trace_context`), so a turn run later or after a restart stays in its trace; message text and tool arguments are recorded as size and hash only unless content capture is on. The Claude runtime gets the turn's `TRACEPARENT`, and, for a loopback collector only, the `OTEL_EXPORTER_OTLP_*` endpoint (scheme, host and port only), a `sevn-cli-claude` service name and `CLAUDE_CODE_ENABLE_TELEMETRY=1`; no export credential ever enters its env. Log records carry the `trace_id` and `span_id` of the span they were written in (never an earlier message's), are exported as OTel logs at INFO and above with secrets scrubbed, and the host exports `sevn.jobs.queued`, `sevn.turns.running`, `sevn.agents.open` and `sevn.ollama.reachable` gauges every 60 seconds, plus a `sevn.otel.dropped` counter for telemetry dropped on a full export queue (every dropped span and log record is counted). `sevn doctor` reports the effective exporter and content setting (`observability_exporter`, `observability_content`), `sevn doctor --check` sends a test export and reports `ok`, `failed: …` or `off`, and `sevn traces test` sends one `sevn.test` span carrying a canary registered as a secret, so it exports redacted, and prints its trace id. `docs/observability.md` covers Logfire, the Datadog Agent and agentless recipes, a generic collector, sampling, content capture, redaction, what each CLI exports, and the failure policy.

- `messages.send` replies once the job is queued instead of holding the response while the turn runs, so a busy host answers sooner and the session can read its next frame.
- mergeCraft reviews run mergeCraft main at 9e4318a, so inline review comments are posted again instead of dropped.
- mergeCraft reports incomplete diff coverage as a warning for now, because it can miss reads the reviewer did make and fail the review job.

- Close shell option-abbreviation approval bypasses, redact tool results before model history, serialize message publication, support confined Git commands in linked worktrees, refresh resolved routing chips and sandbox warnings, coalesce event replay, and retain confirmed sandbox settings after failed updates.

- Fix lane cancellation, crash retry message identity, purge ordering, reroute labels, connection retries, compaction fallback, and confined Git worktree creation.

- Claim jobs atomically on their selected lane, serialize reroutes with turn startup, retain pinned-memory reservations until commit or rollback, and stop live question streams before releasing locks. Claude requires explicit full access and networking; consumed routing messages finish their turns, and numeric output filenames require approval.

- Replace expired operation records before retries, wake idle queued lanes ahead of already-active lanes, release locks after answered question turns, and preserve the original user message when rerouting a started job.

- Preserve worker wake-ups during capacity checks, purge host-managed worktrees with their bot, and retain Linux DNS configuration while hiding service sockets. Avoid double-counting reserved memory promotions and clear moved jobs from their former lane’s queue notice.

- Harden host-side file access against replaced symlinks and keep worktree roots outside bot-writable directories. Hide Linux host service sockets, preserve memory deletion notices across failed turns and restarts, enforce pinned-memory and agent limits, and finish mixed question/approval turns in either answer order. Routing choices use agent ids, invalid fallback targets are rejected, reconnects replay every unprocessed event, and chat clears stale queue labels without duplicating questions.

- Fourth round of bot core review fixes. Cancelling a running turn starts the work queued on that lane and behind the bot's parallel cap. Deleting a memory takes it out of the model's context on the next turn. A memory saved before `user.ask` survives the answer, a cancelled waiting turn drops its staged memory, and moving a message waits for a free slot under the parallel cap. Tests close the worker they bind, so no pump outlives its test.
- Third round of bot core review fixes. Under `auto`, a command that writes through an attached or clustered option (`sort -oout`) or a second operand (`uniq in out`), or a path that only looks like a system program (`/usr/bin/../../tmp/ls`), now asks first. Pinned memories reach every turn of a lane. A lane queued behind the bot's parallel cap starts once an approval or cancel frees the slot. A turn stopped while it resumes an approval is resumed after a restart. A message waiting for a routing choice shows up in an open chat. The web client replays events missed offline even before it saw its first one. A shell timeout or cancel stops background children too, and `mktemp` works in the macOS workspace shell.
- Bot core review fixes: a bot's shell can no longer read other bots' workspaces when the sevn home is outside the user's home, a finished message cannot be moved and run again, moving a waiting job closes its turn, `user.ask` questions stay in the thread, Ollama models can be selected, auto-approved low-risk shell commands finish, cancelling a turn releases its path locks, a follow-up to an idle agent respects the bot's parallel cap, sibling lanes each see memory changes, and CI actions are pinned to commits. A `#` comment no longer hides later lines from the shell risk scorer, creating a worktree runs no checkout filter from the bot's git config, the confined shell gets a writable `TMPDIR`, compaction keeps each tool call with its result, memory and agent tools stay within the caller's bot, `memory.search` returns ids and revisions, and a failed call can be retried with the same `op_id`.
- The workspace shell no longer reads the home directory outside git's config and toolchain installs, keeps no host secrets in its environment, cannot reach the keychain, pasteboard or Apple Events on macOS, and runs in its own namespaces on Linux. Commands time out after 300 seconds, stop with their process group on cancel, and show the model the exit code and stderr. Under `auto` only read-only commands skip approval, `history.read` stays within the bot, and a cancelled queued turn never runs.
- Jev router with a no-key fallback chain, parallel agents with workspace isolation, memories, sandboxed workspace tools, allow_all, compaction, and decision evals (off by default).
- Event replay is paged so a reconnect cannot overflow the session, an approval no longer blocks other calls, and exception text is redacted in logs.
- mergeCraft review runs v0.1.0a4 and can read CI runs.
- Database upgrades keep the initial tables as they shipped, so a later column can be added without colliding, including from a packaged install even when a parent directory has another project's alembic.ini.
- A model error keeps text already streamed and a fixed failure notice, and cancelling a turn survives a restart.
- A crashed turn resumes on startup, a message sent during an approval waits, and a failed turn is reported.
- Bots and agents with Pydantic AI and Claude runtimes; web chat with approvals.
- Spike S3: A2UI v0.9.1 on React and SwiftUI with sevn custom components.
- CI reviews pull requests with mergeCraft on OpenCode Go (DeepSeek V4.1 Flash).

- Foundation: `sevn serve` with WebSocket protocol (handshake, idempotent calls, durable events with replay), SPA shell, Docker image.
