All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Every user-visible code change adds a datestamped bullet under `## [Unreleased]`; those bullets
are cut into a dated, versioned section at release time.

### Security
- [2026-08-08] Sandbox child env now carries `SEVN_PROXY_BINDING_SIG` — the HMAC over the session token's `(container_id, run_id)` pair — pre-computed at spawn time by the gateway (which holds `SEVN_PROXY_SHARED_SECRET`). The job-ops helper reads the signature verbatim and emits it as `X-Sevn-Binding-Signature`, so sandbox-originated egress is no longer rejected with `401` for missing the binding signature; the shared secret stays out of the child env (D1.6/C7.2) while the binding signal still requires a key holder to mint (MergeCraft review #245 follow-up 4b0049b9840bcde02f488190)
- [2026-08-08] Sandbox spawn no longer accepts an existing `SEVN_SESSION_TOKEN` that was minted for a different `run_id` / `container_id`: `_resolve_spawn_session_token` re-checks the token's `run_id` and `container_id` claims against the current spawn context after signature/scope validation and rejects with `403` (`SandboxConfigurationError`) on mismatch, so a token left in the env from a previous run cannot extend into a fresh spawn's binding (MergeCraft review #245 Codex finding 6)
- [2026-08-08] `/web/fetch` re-checks the session-token destination allowlist on every HTTP redirect (streaming + non-streaming) so an allowed host can no longer redirect to an unlisted host and bypass the per-run allowlist (MergeCraft review #245 Codex finding 4)
- [2026-08-08] Proxy binding headers (`X-Sevn-Run-Id`, `X-Sevn-Container-Id`) are no longer decodable from the bearer token alone: callers must now emit an HMAC-SHA256 `X-Sevn-Binding-Signature` over the canonical `container_id=<cid>\nrun_id=<rid>` string keyed by the resolved shared secret, and `llm_post_auth_failure` rejects requests missing or mismatching the signature. The synthetic token-mint fallback on `build_egress_web_headers` (which produced unbounded `_BUDGETS` growth and a constant/replayable run binding) is removed — callers must inject a real per-run scoped `SEVN_SESSION_TOKEN`; the new `ProxySessionTokenRequiredError` surfaces as an actionable `PERMISSION_DENIED` envelope so operators know which env var to wire up (MergeCraft review #245 Codex finding 5 + C7.3 follow-up)
- [2026-08-07] Bump `h2` to 4.4.1 (CVE-2026-71554); pulls `hpack` 4.2.0 with it. `h2` arrives transitively via `httpx[http2]`, so the advisory failed `make security` on every branch until the lock was refreshed
- [2026-08-07] Telegram bot tokens no longer reach the trace backend: httpx client spans put the full URL in `url.full` / `http.url`, which Logfire's scrubber treats as safe keys, so every `https://api.telegram.org/bot<token>/…` request exported the token verbatim. An httpx request hook now redacts the `/bot<token>/` segment on both sync and async clients — rotate the bot token if traces were exported before this change
- [2026-08-07] Logfire scrubbing keeps `sevn.session_id` intact (it previously matched the default `session` pattern and was redacted on every exported span, making traces ungroupable by session); all other default scrub patterns still apply, and the allowlist is a single explicit attribute name

- [2026-08-06] Sandbox egress session tokens are bound to a run and spawn container; the proxy shared secret alone no longer authorizes ``/web/*`` or ``/integration`` (gateway LLM routes and ``/web/auth-check`` keep the service secret)
